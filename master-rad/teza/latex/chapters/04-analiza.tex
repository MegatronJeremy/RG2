\section{Metodologija}
\label{sec:metodologija}

\paragraph{Hardver: cross-vendor postavka.} The central evaluation compares the identical pipeline on
two current-generation GPUs from different vendors: an AMD Radeon RX 9070 XT (RDNA4) and an NVIDIA
GeForce RTX 5070 (Blackwell). Both run the same engine binary, the same HLSL-compiled SPIR-V shaders,
the same render graph, and the same scene and settings; the only variable is the selected physical
device. That identity is the fairness basis of the comparison: any difference in timing is due to the
hardware and its driver, not to a different code path. Table~\ref{tab:gpus} lists the relevant
specifications. Because the algorithm is bit-for-bit identical on both GPUs, the quality metrics
(PSNR/SSIM) are expected to match across them; the cross-vendor result is therefore a performance
comparison, and any quality divergence would flag a non-determinism to investigate rather than a real
difference. The RX 7900 XTX (RDNA3) used during development serves as an optional generational
reference and as the target of the static occupancy analysis (Section~\ref{sec:occupancy}), which is
AMD-only.

\paragraph{Scena.} The test scene is Sponza, a standard interior with strong indirect bounce, lit by
ten lights (three spot, six point, one directional) at a fixed render resolution stated with the
results. A code-generated stress scene (a grid of meshes) is available for scaling tests.

\paragraph{Controls for fair comparison.} Several controls keep the measurements honest and
reproducible. The camera is held static for every A/B comparison: a moving camera desynchronizes the
frame sequence between two runs and fabricates differences that are timing artifacts rather than real
effects. The shader cache is cleared before any GPU metric is trusted, since a stale cache produces
nondeterministic results. Performance baselines are per-machine and per-resolution, because absolute
milliseconds are not comparable across GPUs or output sizes. Persisted console variables are ignored
during a benchmark run so that a leftover setting cannot silently change the configuration.

\paragraph{Performance measurement.} Each render-graph pass is wrapped in a GPU timestamp scope, and
a harness (\texttt{perf-bench}) averages those per-pass timings over a fixed frame budget after a
fifteen-frame warmup that also covers the one-frame timestamp latency. The benchmark sweeps a fixed
matrix of configurations, \texttt{rt-off} $\rightarrow$ \texttt{shadows} $\rightarrow$ \texttt{+ao}
$\rightarrow$ \texttt{+refl} $\rightarrow$ \texttt{+gi}, enabling one more effect at each step, so the
cost of an effect is the difference between adjacent configurations. One caveat applies to that
difference: it equals the Forward-pass delta only for shadows and reflections, which are inline in
the Forward pass. Global illumination and ambient occlusion run as their own half-resolution passes
with separate timestamp scopes, so their cost is read from those per-pass scopes plus the total GPU
time, not from the Forward delta alone. Across vendors, the raw timestamps are converted to
milliseconds using each device's timestamp period, so the per-pass times are directly comparable;
results are reported for both GPUs side by side rather than diffed against a single-machine baseline,
since here the cross-vendor comparison is itself the measurement.

\paragraph{Quality measurement.} Reconstruction quality is measured against a converged
\emph{path-traced} reference (Section~\ref{sec:pathtracer}): a brute-force unidirectional path tracer
with next-event estimation, accumulated over many frames on a static view, which is the correctness
anchor for every effect at once (shadows, ambient occlusion, reflections, and indirect). For each
real-time technique the harness (\texttt{quality-bench}) captures the same tonemapped present as the
reference and reports three image-quality metrics against it: \textbf{FLIP} (a perceptual difference
metric), \textbf{PSNR}, and \textbf{SSIM}. The metrics are averaged over several fixed viewpoints
(atrium, floor, and gallery views of Sponza) so a single view cannot bias the result, which is how
real-time global-illumination and denoiser work is evaluated in practice.

\section{Pore\dj enje sa postoje\'cim re\v{s}enjima}
\label{sec:poredjenje}

This section compares the ray-traced effects against the existing solutions surveyed in
Chapter~\ref{ch:pregled}. The engine implements raster screen-space baselines for ambient occlusion and
reflections (SSAO, SSR; Section~\ref{sec:efekti}), so the comparison is a same-scene, same-camera A/B: the
screen-space version against the ray-traced version, showing the cases the screen-space method
structurally cannot handle (off-screen occluders and reflectors, disocclusion) and the cost
difference (Figure~\ref{fig:rt-vs-ss}). Separately, the real-time hybrid is compared against the
path-traced reference of Section~\ref{sec:metodologija} in FLIP, PSNR, and SSIM, to show how close it comes and
where it diverges. The positioning against production systems (Lumen, RTXGI, ReSTIR) is qualitative:
the contribution is an integrated, measured, openly licensed ray-query implementation, not a system
that beats a production global-illumination solution.

Table~\ref{tab:quality} reports each technique's image quality against the path-traced reference,
averaged over the three viewpoints.
